# index.js 拆分计划

## 📊 当前文件统计
- **index.js**: 1495 行（过大）
- **目标**: 拆分为多个模块，提高可维护性

## 🎯 拆分目标
将 index.js 拆分为以下文件：
1. **middleware.js** - 中间件逻辑
2. **command6.js** - 网易云点歌指令
3. **command9.js** - 落月点歌指令
4. **index.js** - 主入口、初始化、共享函数

---

## 📁 文件结构

### 1. **middleware.js** (~100-150行)
**职责**: 处理音乐卡片的中间件解析

**导出函数**:
```javascript
export function registerMiddleware(ctx, config, logger, logInfo)
```

**包含内容**:
- 中间件注册逻辑
- JSON 消息解析
- 音乐卡片识别（网易云音乐、QQ音乐等）
- 自动执行点歌指令

**依赖**:
- `config` - 配置对象
- `logger` - 日志对象
- `logInfo` - 日志函数

---

### 2. **command6.js** (~400-500行)
**职责**: 网易云点歌指令的完整实现

**导出函数**:
```javascript
export function registerCommand6(ctx, config, logger, logInfo, sharedFunctions)
```

**包含内容**:
- command6 指令注册
- ID 点歌模式
- 歌名搜索模式
- 歌单生成和渲染
- 用户选择处理
- onebot 音乐卡片发送

**依赖**:
- `config` - 配置对象
- `logger` - 日志对象
- `logInfo` - 日志函数
- `sharedFunctions` - 共享函数集合：
  - `parseRenderMode()` - 解析渲染模式
  - `smartGet()` - 智能 GET 请求
  - `fetchNeteaseLyric()` - 获取网易云歌词
  - `generateResponse()` - 生成响应
  - `renderSongList()` - 渲染歌单（文本/图片）

---

### 3. **command9.js** (~400-500行)
**职责**: 落月点歌指令的完整实现

**导出函数**:
```javascript
export function registerCommand9(ctx, config, logger, logInfo, sharedFunctions)
```

**包含内容**:
- command9 指令注册
- ID 点歌模式（支持网易云和QQ音乐）
- 歌名搜索模式（单平台/聚合搜索）
- 歌单生成和渲染
- 用户选择处理
- 平台标签显示（聚合模式）

**依赖**:
- `config` - 配置对象
- `logger` - 日志对象
- `logInfo` - 日志函数
- `sharedFunctions` - 共享函数集合：
  - `parseRenderMode()` - 解析渲染模式
  - `generateResponse()` - 生成响应
  - `renderSongList()` - 渲染歌单（文本/图片）

---

### 4. **index.js** (~300-400行)
**职责**: 主入口、初始化、共享函数

**保留内容**:
- 导入依赖
- 导出配置和常量
- `apply()` 函数 - 主入口
- `parseRenderMode()` - 解析渲染模式配置
- `smartGet()` - 智能 GET 请求
- `fetchNeteaseLyric()` - 获取网易云歌词
- `generateResponse()` - 生成响应
- `renderSongList()` - 渲染歌单（文本/图片）
- 初始化逻辑（ctx.on('ready')）
- 调用各个模块的注册函数

**导出**:
- `name` - 插件名称
- `inject` - 依赖注入
- `Config` - 配置 Schema
- `usage` - 使用说明
- `apply` - 主函数

## 📋 拆分步骤

### 第一步：创建新文件
1. 创建 `lib/middleware.js`
2. 创建 `lib/command6.js`
3. 创建 `lib/command9.js`

### 第二步：提取中间件逻辑
1. 从 index.js 提取中间件代码到 middleware.js
2. 导出 `registerMiddleware()` 函数
3. 在 index.js 中调用该函数

### 第三步：提取 command6 逻辑
1. 从 index.js 提取 command6 指令代码到 command6.js
2. 导出 `registerCommand6()` 函数
3. 传递共享函数作为参数
4. 在 index.js 中调用该函数

### 第四步：提取 command9 逻辑
1. 从 index.js 提取 command9 指令代码到 command9.js
2. 导出 `registerCommand9()` 函数
3. 传递共享函数作为参数
4. 在 index.js 中调用该函数

### 第五步：清理 index.js
1. 删除已提取的代码
2. 保留必要的导入和导出
3. 确保所有函数正确导出
4. 测试功能完整性

## ⚠️ 注意事项

### 1. **依赖传递**
- 所有模块都需要 `config`、`logger`、`logInfo`
- command6 和 command9 需要共享函数集合
- 使用参数传递，避免全局变量

### 2. **函数导出**
- 确保所有共享函数在 index.js 中正确导出
- 使用 CommonJS 或 ES6 模块语法（根据项目规范）
- 检查循环依赖问题

### 3. **配置访问**
- 所有模块通过 `config` 参数访问配置
- 避免直接访问全局配置对象
- 保持配置访问的一致性

### 4. **错误处理**
- 保持原有的错误处理逻辑
- 确保错误日志正确记录
- 用户友好的错误提示

### 5. **测试验证**
- 拆分后测试所有功能
- 确保 command6 和 command9 正常工作
- 验证中间件功能
- 检查日志输出

## 📊 预期结果

### 文件大小对比
| 文件 | 拆分前 | 拆分后 | 减少 |
|------|--------|--------|------|
| index.js | 1495 行 | ~400 行 | -73% |
| middleware.js | - | ~150 行 | 新增 |
| command6.js | - | ~500 行 | 新增 |
| command9.js | - | ~500 行 | 新增 |
| **总计** | 1495 行 | ~1550 行 | +3% |

### 优势
✅ **可维护性提升**: 每个文件职责单一，易于理解和修改
✅ **代码复用**: 共享函数集中管理，避免重复
✅ **团队协作**: 多人可同时修改不同模块，减少冲突
✅ **测试便利**: 可单独测试每个模块
✅ **扩展性**: 新增指令更容易，遵循相同模式

### 劣势
⚠️ **文件数量增加**: 从 1 个文件增加到 4 个文件
⚠️ **导入复杂度**: 需要管理模块间的依赖关系
⚠️ **调试难度**: 需要跨文件追踪调用链

## 📌 概述

本插件具备完整的音乐文件下载和本地保存功能，主要用于 OneBot 协议的音乐卡片发送场景。支持自定义文件名模板、多种传输模式和安全的文件名处理机制。

## 🔧 核心功能模块

### 1. 文件下载 (`downloadFile`)

**位置**: [`lib/utils.js`](../lib/utils.js#L270)

**主要流程**:
1. 确保缓存目录存在 (`ensureCacheDir`)
2. 通过 `ctx.http.file(url)` 下载音频文件
3. 获取 Content-Type 并确定文件扩展名
4. 根据配置生成文件名
5. 将 ArrayBuffer 转换为 Buffer
6. 根据 `fileTransferMode` 决定是否保存到本地
7. 始终生成 base64 编码（供需要时使用）

**返回值**:
```javascript
{
  localPath: string | null,  // 本地文件路径（localPath 模式下）
  base64: string,            // base64 编码字符串
  mimeType: string,          // MIME 类型
  filename: string           // 文件名
}
```

### 2. 文件名模板解析 (`parseFilenameTemplate`)

**位置**: [`lib/utils.js`](../lib/utils.js#L87)

#### 可用占位符

| 占位符 | 说明 | 数据来源 |
|--------|------|----------|
| `${name}` | 歌曲名称 | `data.name` / `data.songname` / `data.title` |
| `${artist}` | 歌手 | `data.artist` / `data.singer` |
| `${id}` | 歌曲ID | `data.id` |
| `${quality}` | 音质 | `data.quality` |
| `${platform}` | 平台 | 传入的 platform 参数 |
| `${time}` | 时间戳 | 自动生成 (YYYYMMDD-HHMMSS) |

#### 文件名安全处理规则

1. **斜杠处理**: 将所有 `/` 替换为配置的字符（默认 `-`）
2. **非法字符移除**: 删除 `<>:"\|?*` 和控制字符 `\x00-\x1F`
3. **空格处理**: 
   - `fileNameKeepSpaces = false`（默认）：空格替换为 `-`
   - `fileNameKeepSpaces = true`：保留空格
4. **分隔符合并**: 清理连续的 `-`、`_` 和空格
5. **首尾修剪**: 去除首尾的分隔符和空白

**示例**:
```javascript
// 输入模板: "${name}-${artist}-${time}"
// 数据: { name: "晴天", artist: "周杰伦/方文山" }
// 输出: "晴天-周杰伦-方文山-20260410-143025"
```

### 3. 文件存储策略

#### 传输模式配置 (`fileTransferMode`)

**位置**: [`lib/config.js`](../lib/config.js#L562)

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| `localPath` | 返回 `file://` 协议的本地路径 | Koishi 和协议端在同一设备 |
| `base64` (默认) | 返回 base64 编码字符串 | 跨设备/容器部署 |

**重要**: 即使使用 `base64` 模式，文件仍会先保存到本地缓存目录，然后读取生成 base64。

#### 文件命名控制

**位置**: [`lib/config.js`](../lib/config.js#L551-L558)

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `renameTempFile` | boolean | `false` | 是否启用自定义文件名 |
| `fileNameTemplate` | string | `${name}-${artist}-${time}` | 文件名模板（不含扩展名） |
| `fileNameKeepSpaces` | boolean | `false` | 是否保留空格 |
| `fileNameSlashReplacement` | enum | `-` | 斜杠替换字符（可选: `-`, `&`, `_`, `,`, ``） |

**命名逻辑**:
```javascript
if (config.renameTempFile) {
  // 使用模板生成文件名
  const parsedName = parseFilenameTemplate(config.fileNameTemplate, data, platform, options);
  if (parsedName) {
    filename = parsedName + ext;
  } else {
    // 模板解析失败，降级到安全歌名或随机 hash
    filename = safeSongname + ext || randomHex(8) + ext;
  }
} else {
  // 直接使用随机 hash
  filename = crypto.randomBytes(8).toString('hex') + ext;
}
```

## ⚙️ 关键代码片段

### 文件下载与保存

```javascript
async function downloadFile(url, data = {}, platform = '') {
  await ensureCacheDir();

  try {
    const file = await ctx.http.file(url);
    const contentType = file.type || file.mime;
    
    const ext = getExtensionFromContentType(contentType);
    let filename;
    
    if (config.renameTempFile) {
      const filenameOptions = {
        keepSpaces: config.fileNameKeepSpaces || false,
        slashReplacement: config.fileNameSlashReplacement || '-',
      };
      const parsedName = parseFilenameTemplate(
        config.fileNameTemplate, 
        data, 
        platform, 
        filenameOptions
      );
      filename = parsedName ? parsedName + ext : fallbackFilename(ext);
    } else {
      filename = crypto.randomBytes(8).toString('hex') + ext;
    }

    const buffer = Buffer.from(file.data);
    let localPath = null;
    
    // 根据配置决定是否保存本地文件
    if (config.fileTransferMode !== 'base64') {
      const filePath = path.join(cacheDir, filename);
      await fs.writeFile(filePath, buffer);
      localPath = filePath;
    }

    // 始终生成 base64
    const base64 = buffer.toString('base64');
    const mimeType = contentType || 'audio/mpeg';

    return { localPath, base64, mimeType, filename };
  } catch (error) {
    logger.error('文件下载失败:', error);
    return null;
  }
}
```

## 💡 使用建议

### 推荐配置

**场景 1: 单机部署（Koishi + OneBot 同机）**
```yaml
renameTempFile: true
fileNameTemplate: '${name}-${artist}-${time}'
fileNameKeepSpaces: false
fileNameSlashReplacement: '-'
fileTransferMode: localPath
```

**场景 2: 分布式部署（Docker/多机器）**
```yaml
renameTempFile: true
fileNameTemplate: '${name}-${artist}-${time}'
fileNameKeepSpaces: false
fileNameSlashReplacement: '-'
fileTransferMode: base64  # 必须使用 base64
```

**场景 3: 多歌手友好命名**
```yaml
fileNameTemplate: '${artist} - ${name} (${quality})'
fileNameSlashReplacement: '&'  # 用 & 替代 / 分隔多个歌手
```

## ⚠️ 注意事项

1. **临时性存储**: 文件保存在缓存目录，可能被定期清理
2. **磁盘空间**: 频繁下载音乐会占用存储空间，建议监控 `cacheDir` 大小
3. **跨设备限制**: `localPath` 模式仅在 Koishi 和协议端同机时有效
4. **性能考虑**: `base64` 模式会增加内存使用和传输开销
5. **文件名冲突**: 相同歌曲多次下载可能覆盖旧文件（取决于时间戳精度）
6. **特殊字符**: 某些系统可能对长文件名或特殊 Unicode 字符支持不佳
